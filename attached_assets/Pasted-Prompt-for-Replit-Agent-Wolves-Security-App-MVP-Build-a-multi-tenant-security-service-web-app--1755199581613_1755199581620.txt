Stack & Project Setup

Frontend: React + Vite + TypeScript, Tailwind CSS, shadcn/ui, React Router, Zustand (state).

Backend: Firebase (Auth, Firestore, Cloud Functions, Storage, FCM).

Maps: MapLibre (open-source) with fallback to Google Maps if an API key is present.

App type: Installable PWA with offline caching for key screens.

Structure: Monorepo or two folders: apps/web and functions.

Add .env support and a sample .env.example.

Auth, Tenancy & Roles (must-have)

Auth: email/password + magic link (passwordless).

Roles: guard, supervisor, client, admin (RBAC).

Multi-tenant isolation: every document includes tenantId. Users have a single tenantId claim.

After sign-in, fetch custom claims and route users to the correct area.

Admin-only “Tenant bootstrap” page to create tenants and invite users (by email).

Firestore Data Model (collections)

tenants: { id, name, billingPlan, createdAt }

users: { uid, tenantId, roles: string[], displayName, phone, status }

sites: { id, tenantId, name, geofence, active }

patrolPoints: { id, siteId, label, location{lat,lng}, radiusM, qrCode, nfcTagId, order }

routes: { id, siteId, name, pointIds: string[] }

shifts: { id, siteId, guardId, startAt, endAt, status }

checkins: { id, siteId, patrolPointId, guardId, timestamp, location, batteryPct, photoUrl, method }

incidents: { id, siteId, createdBy, createdAt, category, severity, description, photos: string[], status, assignedTo, resolvedAt }

alerts: { id, siteId, guardId, type: "SOS", createdAt, location, handledBy, handledAt }

Include audit fields on all writes: createdBy, updatedBy, createdAt, updatedAt.

Firestore Security (minimum rules)

Only authenticated users.

Enforce request.auth.token.tenantId == resource.data.tenantId.

Writes allowed if the user’s role is appropriate:

guards: create checkins/incidents they authored.

supervisors/admins: CRUD on sites/routes/patrolPoints/shifts/incidents/alerts within their tenant.

clients: read-only to reports/incidents for their tenant.
