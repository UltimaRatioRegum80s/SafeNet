❌ New Issue #1 — FEED flicker / rapid switching between incidents and empty state
On mobile in Kenya:
- Feed rapidly flickers between:
  - showing the incident cards correctly, then
  - showing an empty feed state (as if there are 0 incidents),
  - then back again, repeatedly.
- It feels like two competing render states:
  - “incidents loaded” vs “empty / no location / no data”
  are both firing alternately.

Please investigate deeply:
1) Confirm what state transitions are causing this:
   - locationStatus toggling (ok ↔ unavailable/stale)?
   - query enabling/disabling repeatedly?
   - React Query / SWR cache invalidation loop?
   - useEffect dependency loop that triggers refetch/reset?
2) In Feed.tsx:
   - Are we conditionally rendering empty state based on BOTH:
     - `locationStatus` AND
     - `incidents.length` AND
     - `isLoading/isFetching` ?
   - Are we using `pickQueryLocation()` and a stale window in a way that flips between null and lastGood repeatedly?
3) Add temporary console logs (or dev logging) around:
   - locationStatus
   - selected query location (lat/lng)
   - query enabled flag
   - incidents length
   - isLoading / isFetching / error
   to confirm the exact flicker cycle.

Desired behavior:
- Once location is valid (or lastGood valid), the feed should remain stable and show incidents.
- While refetching, show a “loading skeleton” or subtle loading indicator, NOT switch to empty state.

Likely fix approach:
- Ensure empty-state rendering only happens when:
  - query is disabled AND no lastGood exists, OR
  - query completed and incidents truly empty
- Do not render empty state during transient fetches.
