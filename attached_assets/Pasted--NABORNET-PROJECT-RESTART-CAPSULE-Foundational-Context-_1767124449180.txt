Foundational Context for New Conversations
1. What This Project Is
NaborNet is a community safety and situational awareness platform, delivered as an offline-capable Progressive Web App (PWA).
Its purpose is to allow community members to:
report observations and incidents (not accusations),


view unverified, community-submitted reports on a map/feed,


maintain awareness during connectivity loss,


without positioning itself as an emergency service, law enforcement tool, or evidence platform.


NaborNet is explicitly NOT:
an emergency service,


a policing or investigative platform,


a source of verified facts or proof,


a chat-based social network.


The product philosophy is Safety-Grade MVP:
Useful, conservative, legally defensible, and intentionally restrained.

2️⃣ NABORNET — TECHNICAL CONTEXT BRIEF
(For engineers, architects, auditors, or regulators)
System Purpose
NaborNet is a PWA-based community incident reporting system designed for situational awareness, not enforcement or emergency response. All user-submitted content is explicitly unverified.

Deployment State
Environment: Production (Replit-hosted)


Access mode: Closed beta


Signup control: SIGNUP_MODE=whitelist


No public registration endpoints exposed



Architecture Summary
Frontend: React + TypeScript


Backend: Node.js / Express


Auth: Session-based (PostgreSQL store)


Realtime: Socket.IO


Storage: PostgreSQL (primary), IndexedDB (offline)


PWA: Service Worker v2.x, installable manifest



Authentication & Abuse Controls
Email/password auth


Mandatory email verification enforced server-side for:


Online incident creation


Offline sync ingestion


Password reset with token expiry


Login rate limiting (email + IP)


No admin/owner auth bypasses



Incident Integrity
Each incident assigned a client-generated UUID


idempotency_key stored in DB


Partial unique index (WHERE idempotency_key IS NOT NULL)


Duplicate incidents mathematically impossible


Same checks applied to REST and Socket.IO ingestion paths



Offline & Sync Behavior
Offline drafts stored in IndexedDB


Foreground sync on reconnect (no Background Sync dependency)


Retry with exponential backoff


Clear state machine: pending / syncing / synced / failed


Offline location precision reduced


Offline data fully purged on logout


Map tiles explicitly excluded from cache



Legal & Compliance Controls
Terms of Service v1.1.0


Privacy Policy v1.0.0


LegalGate modal blocks access until consent


Versioned consent stored in DB with:


userId


timestamp


IP address


user agent


Anti-doxxing and defamation-mitigation language enforced



Operational Safety
Environment-based kill switches:


INCIDENT_CREATION_ENABLED


OFFLINE_SYNC_ENABLED


Evaluated before DB writes and socket events


Enables rapid shutdown of reporting functionality



Email Infrastructure
Resend integrated


Currently operating in sandbox mode


Verification emails limited to Resend account owner


Domain verification intentionally deferred


Owner account manually verified for beta testing



Explicitly Out of Scope (Current Phase)
Public chat UI (schema exists only)


Push notifications


Media uploads while offline


Production monitoring (e.g., Sentry)


Operator dashboard


Analytics pipeline



Safety Assessment
Conclusion:
 The system is safe for closed beta operation, with controlled access, legal safeguards, data integrity guarantees, and emergency controls in place.
