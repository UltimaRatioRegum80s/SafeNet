Add these resets to client/src/index.css (or wherever you keep global map styles). They make the Leaflet control containers fully transparent, non-blocking, and the buttons still clickable.

/* ---- Leaflet control rail reset: don't cover tiles ---- */
.leaflet-control-container,
.leaflet-top,
.leaflet-bottom,
.leaflet-left,
.leaflet-right {
  background: transparent !important;
  box-shadow: none !important;
}

/* Some custom themes add pseudo-elements; nuke them */
.leaflet-control-container::before,
.leaflet-top::before,
.leaflet-bottom::before,
.leaflet-left::before,
.leaflet-right::before {
  content: none !important;
}

/* Prevent a full-height rail capturing clicks */
.leaflet-left,
.leaflet-right {
  pointer-events: none;             /* container ignores events */
  width: auto !important;
  height: auto !important;
}

/* Allow the actual controls to be interactive */
.leaflet-left .leaflet-control,
.leaflet-right .leaflet-control,
.leaflet-top .leaflet-control,
.leaflet-bottom .leaflet-control {
  pointer-events: auto;
  background: transparent;          /* keep buttons’ own backgrounds only */
  box-shadow: none;
  margin: 0.25rem 0.25rem;          /* tidy spacing */
}

/* Keep Leaflet UI layering sane */
.leaflet-pane,
.leaflet-top,
.leaflet-bottom { z-index: 400; }   /* markers/controls */
.leaflet-popup-pane { z-index: 600; }

Why this works

Somewhere a style (often from a card/utility class or a theme) is applied to .leaflet-left / .leaflet-top that:

stretches it vertically,

gives it a dark background,

sits above the tile pane.

These resets force those containers to be transparent and size to their contents, so you’ll see tiles right under the buttons again.
