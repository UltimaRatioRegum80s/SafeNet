Prompt for Replit — SafeLy/NaborNet Auth (Replit-only storage & resources)

Goal: Implement signup/login using Replit’s server + Postgres + sessions (no Firebase). Store users, roles, country, and city in Replit Postgres. Keep the existing SafeLy/NaborNet UI palette and layout.

Tech constraints (important)

Use existing deps already in the project: Express, express-session, connect-pg-simple, passport, passport-local, drizzle-orm, @neondatabase/serverless (or pg).

Persist to Replit Postgres (Neon) via Drizzle. Read DATABASE_URL from env.

Use server-side sessions (cookie) with express-session + connect-pg-simple. No JWTs, no Firebase.

Passwords must be hashed with bcrypt (or argon2 if already installed).

Keep color palette and styling exactly as in the current Login/Signup page (bg-gradient-to-b from-slate-900 to-slate-800, slate cards, cyan accents). Do not change global CSS or theme tokens.

Server work

Drizzle schema & migration

Create tables:

users:

id (uuid, pk, default gen_random_uuid())

email (text, unique, nullable for anonymous users)

password_hash (text, nullable for anonymous users)

username (text, indexed)

roles (text[]; store ['resident'] or ['security_org'])

country (text)

city (text)

created_at (timestamptz default now())

updated_at (timestamptz default now())

user_handles (optional, for future uniqueness checks): username unique → user_id.

Create session store table via connect-pg-simple (session).

Passport local strategy

POST /api/auth/signup (email/password):

Validate inputs: email, password (≥6 chars), optional username, required role ("private" or "security_org"), required country, required city.

Hash password, create user, map role:

"private" → roles = ['resident']

"security_org" → roles = ['security_org']

Log the user in (establish session) and return { ok: true, user: { id, username, roles, country, city } }.

POST /api/auth/login (email/password):

Verify via Passport Local, then establish session, return user profile.

POST /api/auth/anon-join (Quick Join):

Body: { username, role: 'private'|'security_org', country, city }

Create user without email/password (anonymous), store the fields above, establish session, return user.

POST /api/auth/logout ends the session.

GET /api/auth/me returns current session user (or 401).

Session config

express-session with connect-pg-simple store (use DATABASE_URL).

Secure cookie settings; cookie.sameSite='lax'; cookie.secure true in production.

Add CSRF protection middleware or at minimum check Content-Type: application/json and origin in dev.
